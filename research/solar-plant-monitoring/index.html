Solar Plant Monitoring & Energy Intelligence Platform

Data engineering, analytics, and forecasting for utility-scale photovoltaic power plant performance assessment and operational optimization.

Core contribution

I developed the analytics and forecasting layer of a monitoring platform deployed at a 7.5 MW photovoltaic plant in Mahallat, Iran. My responsibilities span data pipeline design, SCADA integration, performance modeling, machine-learning forecasting, anomaly detection, and fault diagnosis across the platform's three dashboard applications.

The platform ingests meteorological observations (GHI, DNI, DHI, POA, cloud cover, aerosol depth, temperature, humidity, wind) and equipment measurements (inverter power, efficiency, MPPT voltages, grid frequency, phase voltages, environmental sensors) at 15-minute resolution, synchronizes them with plant structure metadata, and presents them through three analytical views: solar resource monitoring, real-time equipment status, and historical performance analysis.

Data Model & Configuration Layer

Plant structure and equipment configuration form the semantic layer that maps SCADA signals to operational entities. This layer ensures data provenance, enables aggregation across hierarchy levels, and supports consistent templating across multi-site deployments.

Entity hierarchy

Company → Plant → Functional Location (e.g. LV Stations) → Equipment (Inverters, Measuring Centers, Sensors, IO Boxes). Each level supports role-based access control, data partitioning, and multi-site management.

Characteristics & Metadata

Quantitative attributes (AC/DC power, efficiency, voltage, current, irradiance, temperature, pressure) are defined with units, valid ranges, acquisition frequency, and storage policy. This ensures uniform treatment across data pipelines.

Template system

Equipment-type templates (e.g. Inverter Monitoring, Weather Station) group standard characteristics. Assignment to instances ensures consistency, reduces configuration drift, and simplifies expansion to new plants.

Structure → Data mapping → Ingestion → Dashboards

Every dashboard value is traceable to a characteristic assigned to an equipment instance within the plant hierarchy. This audit trail is essential for data quality assurance and root-cause analysis in production environments.

Three Analytical Views

The platform provides three complementary dashboards, each addressing a distinct analytical question aligned with operational and managerial needs.

01 / Weather Status Dashboard

This application consolidates solar resource and meteorological inputs essential for performance interpretation. It integrates:

  • Irradiance parameters: GHI, DNI, DHI, GTI, POA with cloud cover, aerosol optical depth, and cloud type classification.
  • Thermodynamic conditions: Air temperature, relative humidity, dew point, surface pressure.
  • Atmospheric effects: Wind speed and direction, precipitation, snowfall, visibility, Rayleigh scattering.
  • Solar geometry: Zenith angle, elevation, azimuth for irradiance model validation.
  • Temporal resolution: 15-minute observations for current day, 1-hour forecast for 72 hours ahead (Jalali calendar).

This module enables rapid assessment of whether generation variations correlate with measurable atmospheric changes, supporting both real-time anomaly detection and retrospective causal analysis of performance shortfalls.

02 / Real-Time Monitoring Dashboard

This application presents liveoperational state of the plant and its equipment. Key features:

  • Plant overview: Aggregated power, yield, efficiency, and system health status.
  • LV station view: Hierarchical drill-down with heatmaps showing per-inverter generation and deviations from cluster mean.
  • Inverter detail: Daily yield, power factor, efficiency, grid frequency, per-MPPT voltage/current, per-phase voltage/current, power and energy profiles.
  • Reporting: 15-minute, hourly, daily, and custom-range exportable reports.

The hierarchical design supports rapid localization of equipment anomalies (e.g. single inverter underperformance, MPPT imbalance, phase asymmetry) and facilitates O&M decision-making during operating hours.

03 / Analysis Monitoring Dashboard

This application supports historical analysis and forward-looking assessment. Core components:

  • Generation comparison: Actual (SCADA-measured) vs. Expected (physics-based simulation) vs. Forecasted (machine-learning predicted).
  • Temporal aggregation: 15-minute, hourly, daily, weekly, monthly, and annual summaries; support for Jalali calendar periods and custom date ranges.
  • KPI dashboards: Efficiency metrics (PR, CF, panel & inverter η, simulation index, prediction accuracy); operational metrics (peak, mean, std-dev, ramp rate, yield); loss decomposition (total, panel, temperature, inverter).
  • Visualization: Both card summaries (for executive overview) and time-series charts (for trend analysis and comparative assessment).

This layer transforms raw measurements into engineered KPIs that quantify plant performance, identify loss mechanisms, and track forecast model accuracy over operational timescales.

Analytics & Forecasting Pipelines

Expected Generation (Physics-Based Simulation)

Expected generation establishes a defensible baseline by modeling plant response to measured environmental conditions. The model incorporates:

  • Plane-of-array irradiance from weather data and site geometry.
  • PV module efficiency as function of irradiance and cell temperature (temperature coefficient).
  • Inverter efficiency curves as function of input power and voltage operating point.
  • System losses (soiling, wiring, transformer, mismatch, clipping, downtime).

Deviations of Actual from Expected signal equipment degradation, operational faults, or unaccounted losses.

Forecasted Generation (Machine Learning)

Multiple candidate models are trained on historical SCADA and weather data to predict generation 1–72 hours ahead:

  • Linear Regression & Ridge: Baseline interpretable models.
  • Random Forest & Gradient Boosting (XGBoost, LightGBM): Capture non-linearities and feature interactions.
  • Support Vector Regression: Kernel-based approach for high-dimensional feature spaces.
  • LSTM & temporal networks: Exploit sequential time-series structure.

Model Selection & Evaluation

Models are compared using multiple metrics to balance bias-variance trade-off:

  • MAE (Mean Absolute Error): Average magnitude of prediction error; robust to outliers.
  • RMSE (Root Mean Square Error): Penalizes larger errors; sensitive to tail events.
  • R² (Coefficient of Determination): Proportion of variance explained; reference to trivial mean-based prediction.
  • F1-Score: Harmonic mean of precision and recall for binary fault classification tasks.

The platform enables adaptive model switching: if monitoring reveals a candidate model achieving better out-of-sample accuracy, it can be promoted to the active forecast. This allows the platform to tune forecasting strategy as seasonal patterns and data quality evolve.

KPI Framework

KPIs are computed from measurements, simulations, and forecasts, grouped into three categories:

Efficiency & Performance

  • Performance Ratio (PR): Ratio of measured yield to yield expected from available irradiance; normalized by inverter efficiency curve.
  • Capacity Factor (CF): Measured energy output as fraction of nameplate capacity over period; accounts for climate and seasonal variation.
  • PV Efficiency: Simulated power output from modules as function of irradiance and temperature; used to isolate module-level losses.
  • Inverter Efficiency: Measured AC power divided by measured DC power; temporal profile shows loading-dependent behavior.
  • Forecast Accuracy: Tracking error between predicted and actual; lower is better.

Operational Metrics

  • Peak Power, Mean Power, Std. Dev: Operational envelope and stability characterization.
  • Ramp Rate: Rate of power change (dP/dt); high ramps indicate cloud transients or equipment switching.
  • Max Ramp Rate: Worst-case instantaneous rate; used to assess grid integration risk.
  • Period Yield: Energy delivered in period; direct measure of production promise fulfillment.

Loss Decomposition

  • Total Loss: Expected minus Actual (in MWh or percentage).
  • Module Loss: Soiling, degradation, mismatch, wiring losses in DC subsystem.
  • Temperature Loss: Reduction in module efficiency due to elevated cell temperature relative to STC.
  • Inverter Loss: Efficiency shortfall and clipping losses in power conditioning.

Technical Scope & Deliverables

Data Pipeline Architecture: Designed ETL workflows integrating SCADA collectors, weather APIs, time-series database (TimescaleDB), and FastAPI backends. Implemented idempotent data synchronization with retroactive gap-filling and schema evolution support for multi-site scaling.

Configuration & Metadata: Architected the entity-characteristic-template system that decouples asset structure from data acquisition. Enables consistent multi-site deployments and supports dynamic equipment addition without schema changes.

Solar Resource Modeling: Implemented position-of-sun and plane-of-array irradiance calculations using meteorological inputs. Validated against empirical data to quantify environmental performance limits.

Performance Analytics: Developed simulators for module behaviour (temperature derating), inverter efficiency curves, and system-level losses. Built automated loss decomposition to isolate environmental vs. equipment-based shortfalls.

Forecasting & Model Selection: Implemented candidate model frameworks (Linear, Tree, Kernel, Recurrent). Built model evaluation pipelines using cross-validation, holdout testing, and online performance tracking. Enables adaptive switching based on real-time accuracy metrics.

Anomaly Detection & Fault Diagnosis: Developed unsupervised (e.g. isolation forest) and supervised (e.g. classification trees) methods for detecting inverter faults, sensor failures, and operational anomalies.

Dashboard & Reporting: Designed three-tier analytical UI (operational, plant-level, and forecast) with temporal aggregation, Jalali calendar support, and export-ready KPI cards.

Impact & Extensibility

The platform deployed at Mahallat provides a production-grade foundation for scaling to additional utility-scale PV assets. Its layered architecture—configuration, data ingestion, analytics, dashboards—decouples each concern and reduces barriers to multi-site expansion.

By connecting environmental observations to equipment-level measurements to plant-level KPIs, the system gives operators a shared language for interpreting performance, prioritizing interventions, and tracking the effectiveness of O&M decisions.
